# Finance Policy v1.3.3 — Settlement Reconciliation Persistence

**Effective:** 2026-10-08 UTC  
**Source:** `FIN-Phase-2E-SETTLEMENT-RECONCILIATION-PERSISTENCE`

## Change summary

Gateway settlement reconciliation is a durable financial event. A successful reconciliation operation must persist the settlement record before the operation is considered successful.

## Rules

1. Settlement reconciliation is allowed only for a payment transaction whose status is `Paid`.
2. Gateway fee, gateway fee tax, and provider adjustment values are recorded from provider evidence; the application must not guess gateway costs.
3. Net settlement is calculated as:

   `Gross payment - gateway fee - gateway fee tax + provider adjustment`

   with currency rounding applied consistently.
4. A payment transaction can have only one settlement reconciliation record.
5. Existing settlement records are returned instead of creating a second deduction.
6. The settlement repository saves the reconciliation record transactionally. An acknowledgement is not successful if persistence fails.
7. Provider settlement ID, provider payment ID, source evidence, reconciliation reference, reconciler and reconciliation timestamp are retained for audit.
8. Settlement records are separate from the customer-facing 5% HealthApp platform service fee. Gateway deductions are settlement/accounting information and are not added as a second customer charge.

## Audit trace

Business payment → paid payment transaction → provider settlement evidence → gateway fee/tax/adjustment → net settlement → reconciliation metadata.
