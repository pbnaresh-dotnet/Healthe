# Finance Policy v1.2.6 — Discount Configuration Governance

**Effective:** 2026-10-08  
**Source reference:** `FIN-Phase-2D-DISCOUNT-CONFIGURATION-GOVERNANCE`

## Rule

Subscription discounts are **outlet-owned configuration**. The application no longer contains a hidden percentage matrix used when an outlet has no configured tiers.

Each active tier defines:
- minimum and optional maximum meal count;
- one-week discount percentage;
- two-week discount percentage;
- one-month discount percentage.

Discount percentages are limited to 0%–100%, and active meal ranges cannot overlap.

## Calculation

The selected persisted outlet tier determines the subscription discount. If no tier matches the meal count, the subscription discount is 0%.

The discount reduces the customer meal/package base before restaurant tax and HealthApp platform service-fee calculation.

Discount codes are separate commercial inputs and are included in the total discount subject to the package gross amount.

## Historical reproducibility

The finance calculation snapshot stores:
- discount tier ID;
- tier meal range;
- tier percentage used;
- configured-tier discount amount;
- discount-code ID;
- discount-code percentage/cap and applied code;
- discount-code amount;
- total discount amount;
- finance policy document version.

Changing a tier or discount code therefore affects only future calculations. Existing subscriptions retain their original financial snapshot.

## Migration / compatibility

Existing demo configuration already contains the previous 0/3/4/5/6% tier structure as persisted data. That structure is now configuration rather than executable fallback logic. New outlets must explicitly configure their commercial discount tiers before relying on discounting.

## Auditor reference

The source reference `FIN-Phase-2D-DISCOUNT-CONFIGURATION-GOVERNANCE` maps the financial rule to the discount strategy, outlet discount configuration service, customer package calculation, and finance snapshot implementation.
