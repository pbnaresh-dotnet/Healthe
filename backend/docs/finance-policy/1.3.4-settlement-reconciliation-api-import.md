# Finance Policy v1.3.4 — Settlement Reconciliation API and Import

**Effective:** 2026-10-08 UTC  
**Source:** `FIN-Phase-2E-SETTLEMENT-RECONCILIATION-API-IMPORT`

## Rules

- Settlement reconciliation is restricted to SuperAdmin finance operations.
- A settlement row must match an existing paid payment using the provider + provider payment ID.
- Amount-only matching is prohibited.
- Duplicate settlement records return the existing reconciliation record.
- CSV imports are exception-oriented: unmatched provider payment IDs are reported and are not silently posted.
- Provider payment IDs are unique per provider at the database boundary.
- Gateway fees, gateway fee tax and provider adjustments remain separate accounting components.
- The import is a normalization layer; the original provider evidence is retained in the settlement source-data field when supplied.

## Standard CSV contract

Required headers:

`ProviderPaymentId, ProviderSettlementId, GatewayFeeAmount, GatewayFeeTaxAmount`

Optional headers:

`OtherProviderAdjustmentAmount, SettledAtUtc, ReconciliationReference, SourceDataJson`

Cashfree settlement reports should be mapped to this normalized contract before import. Cashfree's reconciliation guidance emphasizes stable identifiers such as payment ID, order ID, settlement ID and UTR rather than amount-only matching. urlCashfree reconciliation guidancehttps://www.cashfree.com/blog/ecommerce-payment-reconciliation/

## Audit trace

Provider settlement report → normalized import row → provider payment ID → paid PaymentTransaction → PaymentGatewaySettlement → net settlement → reconciliation reporting.
