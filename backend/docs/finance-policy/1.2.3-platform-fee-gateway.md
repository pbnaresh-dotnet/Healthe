# Finance Policy Version 1.2.3 — Platform Fee and Gateway Cost Treatment

**Effective:** 2026-10-08  
**Status:** Published implementation decision  
**Source references:** `PlatformFeeStrategy.cs`, `appsettings.json`, `appsettings.Development.json`

## 1. Platform service fee

The default customer-facing HealthApp platform service fee is **5.00%** of the configured net meal amount.

Calculation:

`PlatformServiceFee = Round(NetMealAmount × 5.00%, 2)`

The configured value remains overridable through:

`PlatformFees:CustomerServiceFeePercent`

If that setting is absent, the application fallback is **5.00%**.

## 2. Gateway charges

Payment-gateway processing charges are **included within the 5.00% platform-fee economics**.

They are **not added as a separate customer-facing charge or line item**.

The gateway provider's actual fee remains an internal payment/settlement cost and is recorded separately for reconciliation/accounting. It must not increase the customer's platform fee above the configured 5.00% solely because the payment gateway charged a processing fee.

## 3. Customer presentation

Customer pricing must present the platform service charge according to the approved customer-pricing configuration. Gateway processing cost must not be exposed as a separate "gateway fee" merely to recover the provider charge.

## 4. Accounting boundary

The 5.00% platform fee is the customer-facing platform charge. Actual gateway fees are a cost of processing and are reconciled through payment/settlement records.

Future settlement implementation must ensure:

- Gateway fee is recorded against the actual payment transaction.
- Gateway fee is not duplicated as a customer charge.
- Platform revenue and gateway expense remain separately identifiable in the ledger.
- Refunds and settlement reconciliation preserve the original 5.00% platform-fee rule and actual gateway cost.

## 5. Audit requirement

This change is a finance-policy change and must remain versioned. Historical transactions must continue to use the rate captured by their immutable finance calculation snapshot; changing the default to 5.00% must not rewrite previously calculated transactions.

## 6. CA/accountant boundary

This document records the application's implementation rule. The business's CA/tax adviser should validate the final contractual wording, GST treatment, invoice presentation, gateway-fee accounting treatment and applicable tax classification before production financial reporting.
